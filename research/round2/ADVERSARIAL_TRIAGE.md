# Final adversarial triage of Round 2

10 November 2026 · independent, bounded source and design audit · no experiments

**Verdict: reject both proposals as the present conference-oriented research commitment. Do not select a new objective from this round.** This rejects the evidence for committing to a substantial new contribution; it does not establish that either hypothesis is false or that a small undergraduate investigation would be worthless. The state-revocation proposal has a distinguishable counterfactual, but its useful intervention, practical advantage, and selective-repair premise are unverified. The quantization alternative is essentially the already-reviewed conditional direction, with no new evidence that the diagnostic makes a better deployment decision.

The strongest objection to the main proposal is: **“You changed the source of stale inference state from a text edit to a numerical edit, used an established cache-isolation experiment, and proposed an unspecified learned editor. Where is the new principle or operational advantage over restoring the last clean checkpoint and replaying the intervening tokens?”** The present proposal cannot yet answer this. Replacing refusal with another behavior, or adding a hybrid model, does not answer it either.

## Main proposal: a real counterfactual, insufficient contribution

Holding the complete token sequence fixed while changing the numerical processing history is a legitimate intervention. Asking for the original model's state after the **same** history is distinguishable from removing an invalid text span. There need not be a token span whose deletion expresses that target. In a genuine temporary-control session, useful facts acquired during the intervention must survive its withdrawal.

However, “retaining all text” is largely an interface distinction until the experiment shows a consequence. Existing repair work already preserves the information designated for retention. The stronger question here is whether information inside the intervention window can be retained while the intervention's numerical consequence is selectively removed. If a standard learned cache editor or replay heuristic solves this unchanged, applying it to refusal is a task substitution. If the outcome is only a different harmful-assistance rate under different caches, it is a new instance of a known phenomenon. A substantive increment would require an intervention-conditioned repair principle or a demonstrated, reusable boundary on when selective revocation is possible.

The operator need is plausible but not yet demonstrated. A relevant operator must actually (1) keep complete inference state across a control change, (2) require the intervening history, and (3) face a replay cost worth avoiding. Stateless serving or automatic state invalidation on adapter changes provides no such advantage. A permissive edit used for an entire prefill is also not evidence of a deployed temporary safety-control workflow. Validate the workflow and cost first; do not infer demand from the existence of a reversible edit.

The deployment decision is specific: **after disabling the control, continue from a repaired state, or restore the last clean snapshot and replay every subsequent committed token under the original model?** Ordinary clean replay already preserves every token and removes numerical history from the edit. The learned repair must improve its quality/cost trade-off. Compare against replay from the last clean boundary, not always replay from an empty cache. An earlier checkpoint alone is not a memory-preserving comparator. A clean shadow cache maintained continuously is another exact option, but its extra prefill/decode work and resident memory must be charged. A simpler control applied only to the final output pathway is also relevant if it achieves the same intended online behavior without corrupting reusable state.

Require measured switch latency, total session overhead, peak memory, and quality over a prespecified sequence of later queries. Query-specific recovery on the next answer can leave substantial residue for the following answer. Report where replay is already cheap enough; a fourfold improvement on an artificial long-history case does not establish a useful operating region. An approximate functional repair would not establish complete policy erasure or a security guarantee.

## The existing merged checkpoint does not validate temporary hooks

The local writer code forms a low-rank update of the form `ΔW = -λ v(vᵀW)` and targets actual writer modules; see [model.py](../../reproduction/qwen35_9b/heretic-qwen35/src/heretic/model.py), especially the construction around lines 461–543. For a bias-free linear writer, exact arithmetic gives `ΔW z = -λv(vᵀWz)`. A hook implementing that **same update at that writer's output**, with the same direction, scaling and token schedule, is algebraically equivalent. This provides an implementation route, not numerical verification.

A residual-stream hook after adding the skip connection removes a different component. Row normalization, adapter scaling/casts, rounded merged FP16 weights, and the order of floating-point operations also matter. The merged checkpoint's reload agreement does not test any of these hook comparisons. Use frozen stored adapter factors or the actual effective weight delta; do not silently replace them with a freshly calculated ideal projection.

Most importantly, a permanently edited prefill changes processing of every history token. Ordinary temporary steering may act only during assistant decoding, or only over a short interval. Those are different treatments. Define a clean prefix `p`, an active window `w`, and any post-withdrawal history `s`. Both arms encode exactly `p ⊕ w ⊕ s`; only the prespecified processing events in `w` receive the edit, and both arms process `s` cleanly. A merged model can emulate this only if switching follows the identical event schedule. Encoding the whole history under merged weights is an explicitly different model-switching experiment, not evidence about that temporary protocol.

There is also a causal-path issue: a linear-attention `out_proj` runs after that layer's recurrent update. Its perturbation can affect later layers' states, rather than directly modifying its own same-token recurrent state. Writer names alone do not identify the persistent carrier. The corresponding [official v5.22.1 forward](https://raw.githubusercontent.com/huggingface/transformers/v5.22.1/src/transformers/models/qwen3_5/modeling_qwen3_5.py) shows the update/output order and separate single-token versus chunk paths. A broad intervention at many writers cannot establish a unique refusal-memory mechanism.

## Full hybrid-state capture is plausible, unvalidated

The recovered [run manifest](../../reproduction/qwen35_9b/recovery/runs/corrected-v1/qwen35_corrected/results/run_manifest.json) records Transformers **5.22.1**. I inspected that official tag, not an installed local model environment; the runtime wheel's source hash was not independently verified. The [local base configuration](../../reproduction/qwen35_9b/reference/base_model_config.json) has 24 linear-attention and eight full-attention layers.

The [versioned cache implementation](https://raw.githubusercontent.com/huggingface/transformers/v5.22.1/src/transformers/cache_utils.py) stores attention tensors, convolution/recurrent dictionaries, and initialization/history flags. Convolution and recurrent state updates mutate storage. It explicitly reports initialized recurrent caches as not safely croppable; recording convolution history is not recurrent rollback. Therefore, copying an attention-only legacy tuple or cropping KV is inadequate. A valid snapshot needs independent tensor storage plus cache/generation metadata. It must preserve devices and dtypes, and be restored without aliasing. Static-address/compiled execution needs separate validation.

An analytical size check is encouraging for short, batch-one contexts, but proves no runtime fit. From the local dimensions, nominal FP16 attention KV uses about **32 KiB per history token**; nominal FP32 recurrent state is about **48 MiB**, with roughly **1.5 MiB** of FP16 convolution buffers. This estimates about 178 MiB per complete state at 4,096 tokens, or just over 1 GiB at 32,768 tokens, before metadata, allocator overhead, temporary tensors, and weights. Actual state dtype and allocation must be measured. Process arms sequentially; do not retain six GPU clones by default. CPU offload can change both latency and the claimed advantage.

Thus cloning is a credible engineering task, not a demonstrated blocker or a validated free primitive. No current artifact proves alias-free capture/restore, hybrid cached/cold numerical agreement, hook/merged equivalence, or attainable runtime within two quota-hours.

## Why a low-rank repair is still speculation

A low-rank writer update does not imply a low-rank accumulated-state difference. Its effects pass through attention weights, normalization, gates and recurrent dynamics over many tokens. Paired benign captures may fit average state displacement while missing policy effects on sensitive continuations. Successful reconstruction of tensor MSE need not preserve useful memory or remove behavior. Conversely, forcing a low-rank mean difference to zero may simply weaken access to the whole history.

There is no general reason a map from edited state and edit descriptor alone can reconstruct clean state: the edited computation may have lost distinctions that the clean computation retained. If the repair reads the transcript to recover them, count its token processing. Clean test caches are legitimate oracle diagnostics, never deployable repair inputs. State transplantation can import computation from an entire clean run, so oracle rescue is not evidence of reconstructibility; the additional primary work above tests exactly this failure of inference.

Attention/recurrent swaps are interventions on blocks, not clean percentages of a natural mediated effect. The blocks were jointly produced and can become incompatible when mixed. Include the complete 2×2 block swap, with recurrent and convolution state kept together, and examine interaction, incoherence and memory damage. Even a valid within-Qwen carrier result does not show that hybridity caused the effect. Dense/hybrid differences also vary training, weights, architecture details and editor placement.

## Minimum credible experiment, if this direction is later reopened

This is a finite specification of missing evidence, **not authorization to launch it or a recommendation for another research cycle**.

1. **Validate execution first.** On the pinned stack, verify clean snapshot restoration and independent storage; compare clean cached versus clean replay under matched chunk schedules; verify the exact temporary hook, its zero-strength sham and withdrawal. A substantial unexplained numerical discrepancy stops interpretation. Do not demand bitwise agreement between different kernels, but fix a numerical tolerance and show that its variation does not explain behavioral contrasts.
2. **Use one causal treatment and a fixed transcript.** Predefine `p/w/s`, token-level intervention schedule, writer list/strengths and evaluation lag. Compare clean complete state, edited complete state with edit off, clean-attention/edited-recurrent state, edited-attention/clean-recurrent state, an output-energy-matched random-direction history edit, and a zero-strength hook sham. Use original weights in every suffix. Add a small active-edit positive control and complete-state restoration check. Do not select evaluation items because they already show a stale-state flip.
3. **Probe policy and memory independently.** A concrete small design is 12 prefix families × two suffix probes × six arms = **144 completions**, leaving at most 16 for prespecified controls under the existing 160-completion ceiling. One probe checks policy behavior, with harmful and sensitive-safe strata fixed in advance; the other checks facts/relations learned before and during the active window. Each probe starts from an independent restored state. This is an engineering/large-signal pilot, not adequate evidence for ten-point effects, five-point noninferiority, equivalence, or a learned repair. Two quota-hours is a stop cap, not a runtime estimate. Stop at the first cap; report missing cells without selectively dropping bad cases.
4. **Separate identification from usefulness.** The paired difference estimates a controlled effect of numerical history conditional on these supplied tokens. It does not estimate live-session prevalence, where the intervention also changes generated text. Use semantic assistance, withholding, over-refusal, task accuracy and censoring separately; retain unresolved cases, blind labels, and double-review a subset. Cluster by prefix family. Natural-session confirmation must follow any controlled signal.
5. **Only then test a deployable repair.** Freeze a candidate using disjoint training/development pairs. Test on fresh prefixes without access to clean test state. Compare no repair, replay from the latest valid checkpoint, matched partial/local replay, generic state reconstruction, rank/energy-matched shams, and adapted existing repair operators where technically valid. An incompatible dense-only implementation need not be run unchanged, but its idea cannot be declared beaten without a faithful comparator or a clear scoped limitation. Charge training, captures, descriptors, transfers and runtime. Include later unseen queries from the repaired state.

The first four steps could yield a useful undergraduate result: a reproducible bounded state-history effect, an implementation failure caught by controls, or an informative confidence interval. They do not establish selective reversibility. Estimating the proposed 80% removal / five-point utility margins requires a separate, larger confirmation sample and an actual repair.

## Alternative: edit-specific quantization diagnostic

The deployment decision is clearer here: bake a tested edit into compressed weights, retain a floating update, or require behavioral revalidation. However, this round supplies neither new experimental evidence nor a new validated predictor beyond the earlier conditional recommendation.

[QERA's primary methods](https://arxiv.org/html/2410.06040v1), Section III, already formulate expected input-weighted layer-output reconstruction and derive low-rank corrections. [Q-resafe's official ICML 2025 record](https://proceedings.mlr.press/v267/chen25ci.html) establishes quantization-related safety evaluation and patching. Its linked PDF returned an unsupported-content error here; I do not independently assert the detailed training recipe inherited from the earlier review. The [lflare conversion card](https://huggingface.co/lflare/Qwen3.8-Flash-Next-NVFP4-Abliterated) cited by the earlier reports was not independently method-audited in this round; it remains attributed practitioner evidence, not a new verified numerical result.

`E = Q_S(W+Δ) − Q_S(W) − Δ` is a useful accounting identity. Projected, input-weighted error is a reasonable candidate feature. Neither supplies evidence that it predicts semantic edit loss beyond generic error, edit strength and distance to the quantizer's rounding thresholds. A targeted floating correction can itself reapply behavior, so success must be compared against directly retaining or rescaling the original floating edit at the same parameter/runtime budget. A frozen-grid diagnostic and native conversion with refitted scales are different deployment conditions.

The minimum reopening evidence is one frozen edit/quantizer causal contrast separating base damage from edit loss, followed by an untouched prediction test against generic reconstruction and practical conversion baselines. A retrospective feature correlation, one successful repair, or lower refusal-marker counts does not justify the predictor claim. This was already the unresolved bottleneck in the first recommendation; repeating it with a proposed score does not select a stronger objective. **Keep quantization deferred.**

## Kill criteria, negative results and larger-paper requirements

For the main direction, stop the proposed selective-revocation claim if faithful state/hook execution cannot be validated; the off-state effect is practically small with adequate precision; matched generic perturbations explain the result; or rescue occurs only with oracle state and cannot be reproduced by a deployable intervention. Failure of one chosen low-rank repair only rejects that repair at that budget, not all possible separability. A wide pilot interval means unresolved. Do not hunt prefixes, strengths or lag settings until a preferred aftereffect appears.

Stop the operational claim if clean-boundary replay or a simpler matched control achieves the same useful policy behavior and memory at comparable total cost, or if repair only fixes the known next query and fails on later queries. Loss of intervened facts cannot be hidden by averaging memory accuracy with facts from the untouched prefix. The proposed 25%-of-replay switch-time threshold is a prospective preference, not a demonstrated deployment requirement or full cost metric.

For quantization, kill the edit-specific mechanism/predictor claim if generic corrections or the original floating edit match it at equal cost, if held-out predictions add no useful decision value, or if the rule achieves its false-safe target only by rejecting essentially every conversion. A null on a single setting is scoped robustness evidence; it does not establish universal quantization safety.

A strong undergraduate report can document a properly controlled local effect, a failed selective repair, a replay-dominance boundary, or a precise null. Such results are valuable without a new algorithm or broad generalization. They do not become a major-conference contribution merely by adding more prompts.

A credible larger paper on revocation would need an actual reusable repair or principled feasibility boundary, a demonstrated cost/quality decision beyond replay/checkpoint alternatives, independent temporary-intervention schedules, opposite control polarity and unrelated behaviors, longer histories and delayed probes, and confirmation across untouched dense and hybrid checkpoints. It must distinguish within-model carrier evidence from architectural causation. The quantization alternative would instead need prospectively useful prediction across untouched model/quantizer mechanisms, safety-enhancing and unrelated edits, plus native packed deployment accounting. These are separate programs, not a combined requirement to run both. Neither expansion is established affordable by the remaining quota, and neither guarantees acceptance.

**Unresolved decision:** can this project demonstrate a cheap, selective intervention that changes what an operator should deploy, beyond existing replay, reconstruction and retained-floating-edit alternatives? The present record answers neither branch. Existing artifacts justify no GPU or quantization launch on the strength of Round 2 alone. Reopening one branch should depend on the concrete missing evidence above, not a further broad literature round.
